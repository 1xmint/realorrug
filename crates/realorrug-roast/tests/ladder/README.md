# The synthetic verdict ladder

`synthetic-cant-tell.sheet.json`, `synthetic-nothing-ugly-yet.sheet.json`,
`synthetic-sketchy.sheet.json`, `synthetic-rug-mechanics-live.sheet.json` and
`synthetic-rugged.sheet.json` are **not** accepted cases. Every mint in them
says so (`SYNTHETIC-<LEVEL>-NOT-A-REAL-TOKEN`). They are hand-built fixtures,
generated by `crates/realorrug-roast/tests/synthetic_ladder.rs`, one for each
of the five `Level`s -- built because every real capture anyone has reviewed
so far landed on `CantTell`, and nobody had seen what the bot says at the
other four levels.
[`docs/research/0059-what-the-bot-says-at-every-level.md`](../../../../docs/research/0059-what-the-bot-says-at-every-level.md)
quotes their rendered reply and report text and every check's verdict.

They exist so a reviewer can run `realorrug replay` against them by hand.

## Why they are not in `../replay/`

[`../replay/`](../replay/README.md) means one thing: replies the owner has
read and accepted. `accepted_replies_still_pass.rs` enforces that by panicking
on any sheet there with no `.accepted.txt` beside it, so a half-written pair
cannot hide as "no cases yet". Nobody has signed off on what the model says
about any fixture here, so none of them may sit in that directory; when these
files did, they broke that test for every branch in the repository.

Do not add a `.accepted.txt` next to one of these, and do not move one into
`../replay/`, without the owner reading the reply and the report it produces
and saying yes.

## Regenerating them

```bash
cargo test -p realorrug-roast --test synthetic_ladder -- --exact the_five_levels_are_earned_and_recorded
```

The same run rewrites every file here and writes the full transcript --
sheet, report, reply and every check's verdict -- to
`target/synthetic-ladder-report.txt`.
